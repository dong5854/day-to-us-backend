# 개인용 API 토큰

설정의 **API 토큰 → 새 토큰**에서 이름, 권한, 만료 기간을 선택한다. 발급 화면을 닫기 전에 토큰을 비밀 저장소에 보관한다. 같은 화면에서 마지막 사용 시각을 확인하거나 토큰을 폐기할 수 있다. 교체할 때는 새 토큰으로 한 번 호출한 뒤 기존 토큰을 폐기한다.

## 호출

발급 화면의 예시에서 API 주소와 공간 ID를 확인한다. HTTPS로 요청하고 토큰은 Authorization 헤더에 전달한다.

```sh
curl -H "Authorization: Bearer $DAYTOUS_TOKEN" \
  "$DAYTOUS_API_URL/shared-spaces/$SPACE_ID/schedules"
```

각 경로는 `/shared-spaces/{spaceId}` 아래에 있다. 요청 필드와 응답 형식은 백엔드의 Swagger UI에서 확인할 수 있다.

| 경로 | 조회만 | 조회·편집에 추가되는 작업 |
| --- | --- | --- |
| schedules | 월별 일정, 상세, 충돌 목록 | 생성, 수정, 삭제, 충돌 해결 |
| budget-entries | 목록, 상세 | 생성, 수정, 삭제 |
| fixed-expenses | 목록 | 생성, 수정 미리보기, 수정, 삭제 |
| savings | 월별 저축 계획과 기록 | 계획 생성, 수정 미리보기, 수정, 종료 및 개별 기록 관리 |
| expense-categories, payment-methods | 목록 | 생성, 삭제 |

개인용 토큰은 일반 저축에만 접근한다. 연금과 증권 계좌 연결은 앱에서 관리한다. 저축 조회 응답에는 납입자 이름이 포함되며 이메일 필드는 생략된다. 일정 변경은 기존 Google 캘린더 동기화 설정을 따른다. 공간, 멤버, 푸시, 동기화 설정과 토큰 관리 기능은 앱 로그인이 필요하다.

만료 기간은 7일, 30일(기본), 90일이다. 유효하지 않거나 폐기된 토큰으로 허용 경로를 호출하면 401, 공간 또는 권한 범위를 벗어나면 403을 반환한다. 토큰당 분당 120회, 사용자당 신규 발급 분당 5회를 초과하면 429를 반환한다. 이때 Retry-After 헤더만큼 기다렸다가 다시 시도한다. 생성 요청의 응답을 받지 못했다면 목록에서 생성 여부를 확인한 후 재시도한다.

## 배포

운영 PostgreSQL에 `scripts/add-personal-token.sql`을 먼저 적용한 후 백엔드와 프론트를 배포한다. 공간 멤버십 변경 시 기존 토큰은 DB 트리거에서 폐기한다. 로그인 콜백은 일회용 fragment 코드와 HttpOnly 바인딩 쿠키를 사용한다. 운영 프론트와 API는 같은 사이트의 HTTPS 주소를 쓰고, 프록시와 모니터링에서 Authorization 헤더 및 발급 응답 본문을 수집하지 않도록 설정한다.

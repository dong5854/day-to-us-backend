# 저축 기능 운영 및 검증

## 데이터와 API

- `savings_plan`: 공유 공간별 저축 항목, 선택적 월별 납입 규칙, 종료 상태.
- `savings_record`: 납입 양수 / 인출 음수의 원 단위 정수 기록. 가계부 테이블과 분리한다.
- API 경로: `/shared-spaces/{spaceId}/savings`.
- 조회: `GET ?year=2026&month=10`, 항목 생성: `POST`, 수정: `PUT /{id}`.
- 설정 영향 조회: `POST /{id}/preview`, 종료: `DELETE /{id}` (과거 기록 보존).
- 기록: `POST /{id}/records`, `PUT|DELETE /{id}/records/{recordId}`.
- 수정에는 조회 결과의 `version`을 전달한다. 설정 변경 시 미리보기의 추가/삭제/수정 건수를 확인하고 응답의 `token`을 `reconciliationToken`으로 함께 전달한다. 미리보기 이후 데이터가 바뀌면 다시 확인해야 한다.
- 금액은 요청에서 BigDecimal로 받아 원 단위 정수를 검증하고 Long으로 저장한다. 소수 금액을 반올림·절삭하지 않는다.
- 모든 API에서 공유 공간 소속과 대상 항목 소속을 검사하고, 납입자도 같은 공간 멤버인지 확인한다.

## 자동 반영과 기록 보존

- 한국 시간 기준, 등록·수정 직후 도래한 회차를 반영한다. 60초 주기의 배치가 누락을 보완한다.
- `savings.auto-post.enabled=false`로 자동 배치만 비활성화할 수 있다.
- 매월 원래 지정한 일자를 사용하고 해당 일이 없으면 월말로 계산한다. 만기 당일까지 포함한다.
- 부모 항목 행 잠금과 `(plan_id, occurrence_month)` 고유 제약으로 동시 실행을 직렬화하고 중복 생성을 방지한다.
- 직접 수정한 기록과 삭제한 자동 회차는 설정 재조정 및 배치에서 보존한다. 삭제 회차는 tombstone으로 유지한다.
- 정기→자유 변경 시 과거 미수정 자동 내역이 삭제될 수 있으므로 미리보기를 거친다.
- 종료 요청은 멱등적이다. 종료 항목은 이후 배치에서 제외되고 기존 기록은 남는다.
- 월 합계는 실제 기록만 집계한다. 미래 예정은 별도 응답이며 누적액/납입 합계에 포함하지 않는다.
- 은행 연동이 아니므로 실제 이체 여부는 확인하지 않는다.

## 배포 순서

1. 운영 백업 상태를 확인한다.
2. 운영 DB에 `scripts/add-savings.sql`을 적용한다. 새 테이블/인덱스만 추가하며 기존 가계부 데이터는 수정하지 않는다.
3. 백엔드를 배포해 스키마 검증과 인증된 조회를 확인한다.
4. 프론트엔드를 배포한다.
5. 자유 납입과 정기 납입 각 한 건으로 월 집계, 달력, 사후 수정, 다른 공유 공간 접근 차단을 확인한다.

앱을 이전 버전으로 롤백하더라도 저축 테이블을 삭제하지 않는다. 이미 기록된 저축 데이터를 유지하고 다음 배포에 다시 사용한다. 최초 기능 롤아웃 동안 스키마 적용 전에 새 백엔드를 시작하지 않는다.

## 검증

```sh
./gradlew test --tests '*SavingsServiceTest'
./gradlew test
```

통합 테스트는 H2에서 실행한다. 월말/윤년, 과거 회차 생성과 재조정, 수정·삭제 보존, 중복 배치, 권한, 금액 검증, 종료 보존 및 월별 합계를 검사한다. PostgreSQL 운영 마이그레이션과 iOS 실기기 확인은 배포 단계에서 별도로 수행한다.
